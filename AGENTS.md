# AGENTS.md

Инструкции для AI-агентов, работающих с репозиторием `metacritic_dashboard`.

## О проекте

Сервис раз в час собирает с Metacritic новые игры, сохраняет их в SQLite, строит резюме по отзывам и показывает результат в веб-интерфейсе. Постановка задачи — [TASK.md](TASK.md), архитектура — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Стек

- Python, BeautifulSoup для парсинга HTML
- SQLite в качестве БД

## Общие правила

- Перед работой читай `TASK.md`, `docs/REQUIREMENTS.md` и `docs/ARCHITECTURE.md`.
- **Сначала обнови `docs/ARCHITECTURE.md`, потом пиши код.** Любое решение, меняющее архитектуру, модель данных или поведение сервиса, сначала описывается в архитектуре, затем реализуется.
- Если код расходится с `docs/ARCHITECTURE.md` или `docs/REQUIREMENTS.md`, исправь документ или код в том же изменении.
- Не добавляй функциональность, которой нет в требованиях, без согласования с пользователем.
- Не коммить секреты, `.env` и файлы БД (`*.db`, `*.sqlite3`).
- Не делай `git push`, не создавай коммиты и не меняй видимость репозитория без прямой просьбы пользователя.

## Правила ведения CHANGELOG.md

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Файл — [CHANGELOG.md](CHANGELOG.md).

1. **Каждое значимое изменение** (функциональность, исправление, смена схемы БД, изменение архитектуры или зависимостей) записывается в CHANGELOG.md **в том же изменении, что и сам код**.
2. Записи добавляются в раздел `## [Unreleased]`, в конец соответствующей подгруппы.
3. Подгруппы раздела:
   - `Added` — новая функциональность;
   - `Changed` — изменения существующего поведения;
   - `Deprecated` — то, что скоро будет удалено;
   - `Removed` — удалённое;
   - `Fixed` — исправления ошибок;
   - `Security` — изменения, связанные с безопасностью.
   Пустые подгруппы не добавляй.
4. Одна запись — одна строка в виде `- Краткое описание, что изменилось и зачем`. Пиши по-русски, от лица результата для пользователя или разработчика, без имён личных файлов, если это не важно.
5. Не записывай в CHANGELOG мелочи: опечатки, форматирование, рефакторинг без видимого эффекта, правки только комментариев.
6. При выпуске версии раздел `[Unreleased]` переименовывается в `## [X.Y.Z] - ГГГГ-ММ-ДД` (семантическое версионирование), сверху создаётся новый пустой `[Unreleased]`.
7. Не переписывай и не удаляй записи уже выпущенных версий.
