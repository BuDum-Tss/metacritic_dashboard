# Требования

Структурированная версия [TASK.md](../TASK.md). Каждому требованию присвоен идентификатор, чтобы на него можно было ссылаться в архитектуре, коде и CHANGELOG.

Приоритеты: **M** — обязательная часть, **A1** и **A2** — дополнительные части 1 и 2.

## 1. Сбор данных

| ID | Требование | Прио |
|---|---|---|
| R-1.1 | Сервис запускает обработку 1 раз в час | M |
| R-1.2 | За один запуск обрабатывается 20 игр, которые сегодня ещё не обрабатывались | M |
| R-1.3 | Если игры нет в базе — она добавляется, если есть — информация обновляется | M |
| R-1.4 | Первый запуск за день берёт 20 игр из раздела **New Releases** на https://www.metacritic.com/game/ | M |
| R-1.5 | Последующие запуски за день берут игры из раздела **SEE ALL** (сортировка «Новые»): https://www.metacritic.com/browse/game/all/all/all-time/new/. Каждый запуск обрабатывает очередную страницу | M |
| R-1.6 | С началом нового дня выборка начинается заново: сначала New Releases, затем SEE ALL | M |
| R-1.7 | Найденная игра обновляется по собственной ссылке, а не через список новинок: раз в сутки, пока она молодая (30 дней), затем раз в неделю | доп. |
| R-1.8 | Обход загружает за запуск не больше 250 игр: сначала новые, затем повторные визиты | доп. |
| R-1.9 | Токены модели не тратятся, если отзывов нет, их число не изменилось или выборка прежняя | доп. |
| R-1.10 | Обход игр и анализ отзывов идут двумя независимыми конвейерами со своими расписаниями (по умолчанию анализ на 30 минут позже обхода) и лимитами (250 и 40 игр за запуск) | доп. |

## 2. Данные об игре

| ID | Требование | Прио |
|---|---|---|
| R-2.1 | Название игры | M |
| R-2.2 | Картинка-обложка | M |
| R-2.3 | Платформы; для каждой — Metascore и Userscore (платформ может быть много: ps5, ns2 и т.д.) | M |
| R-2.4 | Разработчик | M |
| R-2.5 | Описание | M |
| R-2.6 | Ссылка на видео | M |
| R-2.7 | Общие оценки критиков и игроков (оценка, вердикт, число отзывов, распределение по тональности) | доп. |
| R-2.8 | Дата релиза игры (нужна для трендов рынка) | доп. |

## 3. Отзывы

| ID | Требование | Прио |
|---|---|---|
| R-3.1 | Сервис просматривает отзывы и пишет короткое резюме: что игрокам нравится, что нет | M |
| R-3.2 | Резюме по отзывам критиков и по отзывам пользователей делаются отдельно | M |
| R-3.3 | Резюме может обновляться при повторных обходах | M |
| R-3.4 | Каждый пункт резюме связан с отзывами, на которых он основан | доп. |
| R-3.5 | По клику на пункт резюме в интерфейсе список отзывов фильтруется до отзывов этого пункта; повторный клик снимает фильтр | доп. |
| R-3.6 | Резюме строится по тексту отзывов, а не по оценке: модель сначала разбирает каждый отзыв, итог проверяется на согласованность с разбором | доп. |

| ID | Требование | Прио |
|---|---|---|
| R-4.1 | Список загруженных игр с краткой информацией по каждой | M |

| R-4.3 | Фильтр по платформам | M |

| R-4.5 | Сортировка по рейтингу | M |

| R-4.7 | Клик по названию похожей игры открывает её карточку | M |
| R-4.8 | Оформление оценок как на Metacritic: критики в квадратах, игроки в кругах; карточки платформ; блок отзывов с вкладками «критики» и «игроки», резюме ИИ слева и отзывами справа | доп. |
| R-4.9 | Описание игры в карточке по умолчанию свёрнуто до границы обложки | доп. |

| R-4.11 | Похожие игры показываются каруселью | доп. |
| R-4.12 | У игры одна единая оценка (среднее по платформам) в списке, сортировке и справа в шапке карточки | доп. |
| R-4.13 | Главная страница — дашборд анализа рынка: показатели, карта успеха (качество и внимание), жанры, расхождения критиков и игроков, ритм релизов | доп. |
| R-4.14 | Под дашбордом карусель недавних релизов с кнопкой «Смотреть все», ведущей в полный список с пагинацией | доп. |
| R-4.15 | Пункты резюме «нравится» и «не нравится» различаются цветом (зелёный и красный), заголовком и значком | доп. |
