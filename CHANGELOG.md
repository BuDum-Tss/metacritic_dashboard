# Changelog

Все значимые изменения проекта фиксируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версионирование — [SemVer](https://semver.org/lang/ru/).
Правила ведения описаны в [AGENTS.md](AGENTS.md).

## [Unreleased]

### Changed
- Резюме видео пишется по-английски, как резюме отзывов и транскрипт; миграция 0016 ставит в очередь на перестроение резюме, уже построенные по-русски
- Миграция 0013 склеивает в предложения уже сохранённые субтитры (например, транскрипт Зельды) и убирает из них маркеры `>>`
- В мониторинге списки запусков по умолчанию свёрнуты
- Жанры на дашборде: таблица только с числами, без полосок, высотой с карту успеха, список прокручивается
- Пояснение к резюме ИИ (размер выборки, модель, время, смещение оценок критиков) спрятано под значок «i»; подсказка исчезает, когда курсор уходит с иконки; значки «i» выровнены по правому краю заголовков

### Fixed
- Таблица жанров на дашборде показывает все жанры с тремя и более играми, а не десять самых частых: жанры с хорошими оценками, но небольшим числом игр (например, Point-and-Click) раньше пропадали; «оценок на игру» считается только по играм с оценками, у жанров без них стоит прочерк, а не ноль
- Полосы прокрутки в тёмной теме больше не светлые: цвета берутся из темы
- Поиск не берёт летсплеи без комментариев (в названии No Commentary, without commentary, commentary free, no talking, [NC]) и игрофильмы (Game Movie, Full Movie, All Cutscenes): в них нет слов автора, резюмировать нечего. Миграция 0017 убирает уже найденные такие ролики вместе с их транскриптами и резюме, и игра ищется заново
- Резюме видео строится только по словам самого автора: каждый яркий момент теперь содержит цитату, которая проверяется по тексту, и пометку, кто говорит (автор или игра); события сюжета без реакции автора, реплики героев и выдуманные моменты отбрасываются, а заключение рассказывает о переживаниях автора, а не пересказывает сюжет. В списке моментов показана цитата
- Резюме видео не принимает реплики героев игры, рассказчика и текст, который игрок читает вслух, за мнение или реакцию автора: модели прямо сказано различать речь автора и речь игры, сомнительные строки пропускаются
- Резюме видео больше не бывает репликой модели вместо текста («готов написать заключение…»): ответ берётся из тегов `<conclusion>`, плохой ответ запрашивается заново, а при старте сервис сам ставит в очередь на перестроение резюме, построенные более ранней версией запроса
- Стрелки и точки переключения медиа (обложка, трейлер, летсплей, обзор) больше не заходят за шапку при прокрутке

### Added
- Английский интерфейс и тёмная тема: настройки языка (RU/EN) и темы (светлая, тёмная, системная) в шапке справа, выбор запоминается в браузере; по умолчанию язык браузера и системная тема
- Кнопка «Проанализировать все» после транскриптов строит и резюме; состояние серии учитывает оба. Миграция 0015 ставит в очередь резюме для уже готовых транскриптов, сервис строит их в фоне после старта
- Резюме видео по кнопке на вкладке «Резюме»: модель выделяет из транскрипта яркие моменты (проблемы и положительные реакции автора, оценки механик, сюжета, арта) и пишет по ним заключение со ссылками по словам на таймкоды; клик по ссылке перематывает плеер. Таблица `video_summaries`, `GET`/`POST /api/games/{id}/summaries/{video_id}`
- Транскрипт видео по кнопке на странице игры: субтитры YouTube, а если их нет — распознавание речи через OpenRouter (`OPENROUTER_API_KEY`); у плейлиста расшифровываются все видео, повторное нажатие доделывает неготовые. Таблица `video_transcripts`, `GET`/`POST /api/games/{id}/transcripts/{kind}`
- Раздел «Видео» в карточке игры: над плеером серии с иконками состояния и кнопка «Проанализировать все»; пока видео не проанализировано, показан только плеер по центру, после этого слева текст с горизонтальными вкладками «Транскрипт» и «Резюме» (пока пустая), справа плеер; в транскрипте прокручиваемый список с таймкодами (клик перематывает видео)
- Субтитры YouTube склеиваются в предложения, чтобы транскрипт читался; маркер смены говорящего `>>` убирается из текста и начинает новое предложение
- Поиск игр учитывает название, жанры, разработчика и описание: слова запроса могут относиться к разным полям, игры с совпадением в названии идут первыми
- Поиск игр ищет не только по названию, но и по жанру
- Таблица жанров на дашборде сортируется по клику на метрику (Metascore, Userscore, оценок на игру), по умолчанию по числу оценок на игру
- Поиск видео начинается с самых популярных игр (больше отзывов критиков и оценок игроков), а не с самых новых: ограниченная квота YouTube уходит на игры, у которых видео скорее всего есть
- Мониторинг: таблицу запусков каждого конвейера можно свернуть и развернуть, выбор запоминается в браузере
- Видео с YouTube: для каждой игры ищутся самый популярный летсплей и обзор (YouTube Data API, нужен ключ `YOUTUBE_API_KEY`); многосерийный летсплей сохраняется плейлистом, а показывается его первое видео. Третий конвейер `videos` со своим расписанием, лимитом и записью в журнале запусков, таблица `game_videos`, видео в карточке игры (`videos`)
- Видео с YouTube принимаются, если вышли не раньше чем за 14 дней до релиза игры (запас для обзоров по снятию эмбарго); срок проверяется и в запросе, и по дате публикации ролика
- Поиск видео берёт только англоязычные ролики: подсказка `relevanceLanguage=en` в запросе, проверка языка видео, а если он не указан, только латиница в названии; русские слова убраны из признаков вида видео
- В слайдере шапки карточки после обложки и трейлера появились летсплей и обзор с YouTube (плеер загружается только на показанном слайде), под шапкой ссылки на ролики и плейлист
- Мониторинг: третий блок «Видео YouTube» с кнопкой запуска и пометкой «YouTube не настроен», если нет ключа
- Деплой передаёт секрет `YOUTUBE_API_KEY` в `.env` на сервере
- Миграция возвращает игры с несколькими платформами в очередь анализа: их резюме пересчитаются в ближайших запусках по отзывам всех платформ, не дожидаясь суток
- Карточка игры в списке стала компактнее: обложка фиксированного соотношения 16:9, оценки справа в одной строке с разработчиком и жанром
- Отзывы для резюме собираются со всех платформ игры, а «всего отзывов» считается по всем платформам (критики: сумма, игроки: общее число оценок); подпись выборки спрятана под значок «i» и объясняет, почему отзывов с текстом меньше
- Пояснения на дашборде спрятаны под значок «i» (открывается по наведению, фокусу и клику)
- В блоке «Где критики и игроки расходятся» разрыв до 10 баллов считается согласием: в списки попадают только игры с разрывом больше 10, сам разрыв в строках не показывается
- Миграция помечает игры без даты релиза как «пора проверить»: даты заполнятся в ближайших запусках обхода, а не через сутки
- Блок отзывов переделан: две вкладки (критики и игроки), слева резюме ИИ с пунктами «нравится» (зелёные) и «не нравится» (красные), справа отзывы; клик по пункту фильтрует отзывы
- Резюме по отзывам строится через разбор каждого отзыва по тексту (а не по оценке) и проверку согласованности: пункты «не нравится» не остаются пустыми, если модель нашла претензии; версия запроса позволяет автоматически перестраивать старые резюме, разбор сохраняется
- Резюме ИИ вынесено из вкладок в две колонки («нравится» и «не нравится») над списком отзывов; клик по пункту фильтрует отзывы, повторный клик снимает фильтр
- Дашборд анализа рынка на главной странице: плитки, карта успеха (качество и внимание), жанры, расхождения критиков и игроков, ритм релизов; под ним карусель недавних релизов со «Смотреть все»
- Дата релиза игры (из страницы игры): показывается в карточке, есть сортировка по дате релиза
- Журнал игр запуска: для обхода и анализа сохраняется, какие игры обработаны и с каким итогом (новая, обновлена, резюме построено, без изменений, ошибка); в мониторинге список раскрывается по клику на запуск
- Два независимых конвейера: обход (до 250 игр в час, загрузка страниц, повторные визиты) и анализ отзывов (до 40 игр, на 30 минут позже), у каждого своё расписание, лимит и блокировка; анализ выбирает игры по данным БД и не тратит запросов и токенов, пока число отзывов не изменилось
- Мониторинг показывает оба конвейера отдельно, у каждого своя кнопка запуска; видно, настроена ли модель
- Открытие новых игр по спискам и повторные визиты по собственной ссылке игры с расписанием (раз в сутки 30 дней, затем раз в неделю) и лимитом на запуск: игры больше не теряются, когда выпадают из списка новинок
- Проверки перед обращением к модели: нет отзывов, число отзывов не изменилось, выборка прежняя — токены не тратятся, страницы отзывов не загружаются
- Единая оценка игры (среднее по платформам): в списке одна пара оценок вместо оценок по платформам, справа в шапке карточки; сортировка по рейтингу идёт по ней же
- Обложка и трейлер игры в одном слайдере (трейлер открывается листанием), похожие игры каруселью
- Общие оценки игры (Metascore и Userscore с вердиктом, числом отзывов и распределением по тональности) собираются со страницы игры, хранятся с историей и показываются в карточке
- Карточка игры в стиле Metacritic: оценки критиков в квадратах, игроков в кругах (и в списке игр), оценки по платформам карточками, описание свёрнуто до границы обложки, блок отзывов с вкладками по тональности и резюме ИИ
- Резюме по отзывам: для каждой игры отдельно по критикам и игрокам модель (`claude-haiku-5-5` по умолчанию, OpenAI-совместимый API) пишет на английском пункты «что нравится» и «что не нравится»; пересчёт не чаще раза в сутки и только при изменении отзывов
- Сбор отзывов из HTML Metacritic (блок на странице игры и страницы отзывов по платформам), выборка с расслоением по тональности, лимитами и воспроизводимым порядком
- Каждый пункт резюме связан с отзывами, на которых он основан; выборка отзывов хранится в БД; карточка игры показывает резюме и по клику на пункт открывает эти отзывы
- Миграции БД на Alembic (применяются при старте); база, созданная до миграций, получает метку базовой версии
- Настройки `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, `SUMMARY_MIN_INTERVAL_HOURS`, `CRITICS_SAMPLE_LIMIT`, `USERS_SAMPLE_LIMIT`, `REVIEW_TEXT_LIMIT`; без ключа резюме не строятся
- В архитектуру и схему БД добавлены анализ отзывов и резюме: источники отзывов (HTML), выборка с расслоением по тональности, запрос к LLM, версии резюме, связь пунктов с отзывами, миграции Alembic
- Требования R-3.4 и R-3.5: связь пунктов резюме с отзывами и показ отзывов по клику
- Деплой записывает `~/app/.env` на сервере из секретов и переменных GitHub (секрет `LLM_API_KEY`, переменные `LLM_BASE_URL`, `LLM_MODEL`, `SITE_ADDRESS`)
- Деплой на VPS: Docker-образы бэкенда и фронтенда, `docker-compose.yml`, Caddy в роли веб-сервера, GitHub Actions для проверок (CI) и автоматического деплоя по SSH через GHCR
- API игр: `GET /api/games` (поиск по названию, фильтр по платформе, сортировка по Metascore, Userscore, названию и дате, постраничная выдача), `GET /api/games/platforms`, `GET /api/games/{id}` с похожими играми (коэффициент Жаккара по жанрам и бонус за общие платформы)
- Веб-интерфейс (`frontend/`): список игр с поиском, фильтром платформ и сортировкой (состояние в адресной строке), карточка игры с оценками по платформам, видео и похожими играми, страница мониторинга с ходом цикла в реальном времени, журналом запусков и кнопкой принудительного запуска
- В архитектуру добавлены интерфейс источников данных `GameSource` (Metacritic сейчас, Steam позже), SQLAlchemy и Pydantic; в схему БД — `games.source` и `sync_runs.batch_index`
- Каркас `backend/` (pyproject, `.env.example`, конфиг) и `frontend/`
- Источник данных Metacritic (`backend/app/sources/`): интерфейс `GameSource`, HTTP-клиент с паузами и повторами, парсеры списков и страницы игры, `MetacriticSource` с тестами на сохранённом HTML
- Планировщик APScheduler (запуск при старте и раз в час), фабрика приложения `create_app` и API синхронизации: `GET /api/sync/status`, `POST /api/sync/run`, `GET /api/sync/runs`; время в API отдаётся в UTC
- Слой БД (`backend/app/db/`): модели SQLAlchemy, сессии, репозиторий (`save_game`, история метрик, журнал запусков) с тестами
- Описание задания (`TASK.md`) и первоначальная архитектура (`docs/ARCHITECTURE.md`)
- `AGENTS.md` с правилами для агентов, правилом «сначала архитектура, потом код» и правилами ведения CHANGELOG
- `docs/REQUIREMENTS.md` со структурированными требованиями
- Схема БД вынесена в `docs/DATABASE.md`: игры, жанры, платформы, история метрик, версии резюме, журнал запусков `sync_runs`
- В архитектуру добавлены структура проекта (backend/frontend) и результаты анализа HTML Metacritic: источники данных списков и страницы игры
- Пачка за запуск — ровно 20 игр, номер пачки за день хранится как `batch_index` в `sync_runs`
- В архитектуру добавлены стек (FastAPI, APScheduler), запуск по расписанию, выбор пачки игр и обнаружение изменений по хэшу
